## Design Finding (flagged for T7_4)

`tokenRequests.type` is a **one-way, CEL-enforced transition** on the singleton `ClusterCSIDriver` — once set to `"Managed"` it can never revert to `"Unmanaged"` for the rest of an e2e run. This means `T7_3` and `T7_4` are **not actually safely parallel/order-independent** for the `Unmanaged`-dependent scenarios, contrary to the `Parallel OK: Yes` annotation in `tasks.md`/`plan.md` §3.

**Resolution applied**: `T7_3`'s `Managed`-audience calls are wired at the bottom of `hack/e2e.sh`'s execution block, immediately after an explicit comment marker stating this is the *last safe insertion point* for any `Unmanaged`-dependent scenario. **`T7_4` must insert its `Unmanaged`-preservation scenario calls before this marker** (a reorder, not just an append) when it is implemented next.
