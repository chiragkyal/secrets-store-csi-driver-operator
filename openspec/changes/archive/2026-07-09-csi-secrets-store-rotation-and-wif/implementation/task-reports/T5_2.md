## Summary

Extended `hack/e2e.sh` with two new test functions covering US2 (single WIF token audience, SC-003) and US4 (multiple simultaneous WIF token audiences, SC-004): `test_wif_single_audience` and `test_wif_multi_audience`. Per this task's explicit Non-goals, both verify the `storage.k8s.io` `CSIDriver.spec.tokenRequests` field and that a workload can still mount a secret via the driver while `tokenRequests` is configured — not a full cloud-provider (AWS STS / Azure AD) authentication round-trip, which is outside this operator's scope and unsupported by this repo's `e2e-provider` fixture.

While implementing, identified a real, by-design constraint that shapes correct test cleanup: once `tokenRequests.type` is set to `Managed` (FR-006), it can never be reverted to `Unmanaged` — only the audience list can be emptied (FR-007). Added a dedicated `test_wif_clear_audiences` helper implementing that FR-007 cleanup path, called by both tests before the generic `test_driver_config_restore` (from T5_1), so the test suite leaves the cluster in the correct, spec-compliant clean state rather than attempting an invalid full reversion.
