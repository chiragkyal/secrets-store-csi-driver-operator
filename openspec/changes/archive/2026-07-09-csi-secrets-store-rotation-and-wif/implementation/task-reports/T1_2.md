## Deviations

**Unplanned `client-go` bump.** The task payload's `Implementation notes` said client-go might be needed "if new apply-configuration types are needed for `ExtractClusterCSIDriver`" — and T1_1's report concluded client-go was **not** needed for that reason (no `SecretsStore` apply-configuration exists upstream, and this feature only reads `DriverConfig`, never applies it via SSA). That conclusion was correct as far as it went, but `go build` surfaced a **different, unrelated** reason client-go needed a bump anyway: version skew. The previously-pinned `client-go` (`v0.0.0-20260302182750-20813ce71ca6`, March 2026) vendors `config/v1alpha1` listers/apply-configurations referencing `configv1alpha1.ClusterImagePolicy`/`ImagePolicy`/etc. types that no longer exist in the same form in the newly-bumped `openshift/api` (July 2026) — a pre-existing upstream compatibility contract between the two repos that this operator has no control over. Resolved by bumping `client-go` to its own current `master` HEAD (`24d059aea27a`, 2026-07-03), which restored compatibility. This is a reasonable, minimal, in-scope fix (still just a `go.mod`/`vendor` regeneration, per this task's Target files) — not a deviation from the task's *intent*, just from its narrower initial hypothesis about *why* client-go might need touching.
