## Findings

| Mechanism | How it inherits gating |
|---|---|
| `WithSecretRotationDaemonSetHook` | Called from `CSIDriverNodeServiceController.getDaemonSet()`, itself only reachable via `syncManaged()`/`syncDeleting()` — both gated behind `sync()`'s `ManagementState` check. The hook only mutates the in-memory `*appsv1.DaemonSet` passed to it; the actual `resourceapply.ApplyDaemonSet` write happens afterward, inside the already-gated `syncManaged()`. |
| `NewDynamicCSIDriverAssetFunc` (via `"SecretsStoreDynamicCSIDriverController"`) | Gates on the identical `shouldCreateFn`/`shouldDeleteFn` (`getOperatorSyncState(...) == Managed`/`== Removed`) as the pre-existing shared call. The `AssetFunc` itself only returns bytes; the actual `resourceapply.ApplyDirectly`/`ApplyCSIDriver` write is only invoked by `StaticResourceController.Sync()` after gating passes. |

Confirmed via `grep -n "kubeClient\.\|dynamicClient\.\|\.Create(\|\.Update(\|\.Delete(\|\.Apply(" pkg/operator/rotation.go pkg/operator/csidriver_asset.go`: **zero matches** — both files are purely read-only (via listers) plus in-memory mutation; no direct cluster-write path exists that could bypass gating.
